# dht22-wasm-gui — browser GUI (Rust + WebAssembly)

A JavaScript GUI with logic compiled from Rust to WebAssembly. It spawns an
**iroh endpoint** in the browser (compiled to `wasm32-unknown-unknown`), shows its
endpoint ID, and acts as a **dual-DHT22 sensor client** — the browser equivalent of
the native [`dht22-gui`](../dht22-gui) CLI.

It speaks the same `SENSOR_ALPN` irpc service ([`dht22-proto`](../dht22-proto)) as
the CLI and the ESP32 server, and runs the **same live polling logic**: backfill a
window of history (one ranged `GetLog`), then each tick fetch only the records newer
than the last one seen via incremental `GetLog`, with device-restart detection.
Paste a ticket, hit **start live feed**.

The Rust/wasm side is *just* the iroh + `dht22-proto` data path — it serializes each
`Record` and hands it to JS. Presentation lives in [`public/main.js`](public/main.js):
a temperature/humidity **chart over time** (left axis °C, right axis %RH; inside +
outside) drawn with [uPlot](https://github.com/leeoniya/uPlot), plus a text log of
every record in the same layout as the CLI's `println!`. uPlot is vendored under
`public/vendor/` so the static site has no runtime CDN dependency.

> Browsers can't open UDP/QUIC sockets, so this endpoint is **relay-only**. The
> ticket you paste must carry a relay URL — i.e. come from the relay-capable
> (**PSRAM**) [`server-esp32-spiram-dht22`](../server-esp32-spiram-dht22), not the
> bare-metal / no-SPIRAM variants.

The endpoint/identity scaffolding mirrors the
[`browser-echo`](https://github.com/n0-computer/iroh-examples/tree/main/browser-echo)
example from iroh-examples.

## Layout

```
dht22-wasm-gui/
├── Cargo.toml          # cdylib crate, wasm-bindgen pinned to the installed CLI
├── src/lib.rs          # #[wasm_bindgen(start)] + Node::{spawn, subscribe}
└── public/             # static site, served as-is
    ├── index.html
    ├── main.js         # data → text log + uPlot chart; calls into wasm
    ├── style.css
    ├── vendor/         # uPlot (js + css), vendored — no runtime CDN
    └── wasm/           # GENERATED by `wasm-bindgen` (gitignored)
```

## Prerequisites

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli   # must match the wasm-bindgen crate version (0.2.100)
```

`python3` is used for the static server (no npm dependencies required).

## Build & run

```sh
npm run build      # cargo build (wasm) + wasm-bindgen -> public/wasm/
npm run serve      # python3 http.server on :8080
```

Then open <http://localhost:8080>. Paste the ticket the ESP32 prints on startup
and hit **start live feed** — new sensor records stream into the log as they land.

For faster iteration with debug symbols: `npm run build:debug`.

> Note: a static `file://` open won't work — `wasm-bindgen --target web` emits an ES
> module that must be served over HTTP.
